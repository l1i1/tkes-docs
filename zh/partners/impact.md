# 公益智能扶持计划

Tokeness 面向开源项目、公益项目和社会化企业开放公益智能扶持计划。入选项目可获得每月 `1000 万 - 50 亿` tokens 的 AI API 支持，用于开发、运营、知识服务、内容生产、自动化处理和公共服务场景。

公益额度以 `MiMo-V2.5` 作为基准模型核算。项目可以使用其他模型，实际消耗按 Tokeness 平台模型价格、模型权限和等价额度规则折算。

## 支持对象

| 类型 | 说明 |
| --- | --- |
| 开源项目 | 面向开发者工具、基础设施、教育资源、无障碍技术、公共数据、AI 安全等方向的开源项目 |
| 公益项目 | 面向教育、医疗、环保、灾害响应、心理健康、乡村服务、弱势群体支持等领域的公益组织或公益行动 |
| 社会化企业 | 以商业方式解决社会问题的企业，例如普惠教育、助残就业、可持续消费、社区服务和公益科技 |

## 额度档位

公益额度按月发放，不折现、不退款、不转售，未使用额度默认不滚存。

| 档位 | 每月基准额度 | 适合对象 |
| --- | ---: | --- |
| Starter | 1000 万 tokens | 已有官网首页、公开仓库或项目发布页的早期项目 |
| Builder | 5000 万 tokens | 有真实用户、社区或受益人的项目 |
| Growth | 1 亿 tokens | 有稳定使用场景和可量化影响目标的项目 |
| Impact | 5 亿 tokens | 服务规模较大、已有成熟运营机制的项目 |
| Strategic | 50 亿 tokens | 高影响力基础设施、重点公益平台或联合项目 |

`Strategic` 档位需要单独评审，必须按周、按 Key 或按项目分批释放额度，并接受周度或月度复核。复核不通过时，Tokeness 可降低档位、暂停后续释放或调整模型范围。

## 申请前置要求

申请前，项目方需要先在指定公开位置添加 Tokeness 支持声明。未添加、位置不符合要求或无法公开访问的项目，不进入额度评审流程。

可放置位置按项目公开载体选择：

| 位置 | 示例 |
| --- | --- |
| 公开仓库 | GitHub、Gitee、CNB 等仓库的 `README.md` |
| 项目官网 | 网站首页必须展示，建议放在首页页脚 |
| 无官网且无公开仓库 | 项目发布页底部、项目动态末尾、博客文章末尾或公众号文章末尾 |

如果项目同时有官网和公开仓库，优先放在官网首页页脚或仓库 `README.md`。赞助页、合作伙伴页、文档页、二级页面或临时公告不能替代首页页脚或仓库 `README.md`。

仓库 `README.md` 推荐写法：

```md
<p>
  本项目的 AI API 支持由
  <a href="https://tokeness.io">
    Tokeness.io
  </a>
  赞助提供。
</p>
```

网站页脚或发布页底部写法：

```html
本项目的 AI API 支持由
<a href="https://tokeness.io" target="_blank" rel="noopener">
  <img src="https://docs.tokeness.io/logo.svg" alt="Tokeness" height="24">
  Tokeness.io
</a>
 赞助提供。
```

Tokeness 会在申请审核和续期审核时检查该链接是否仍然公开可访问。未展示 Logo、未链接到 `https://tokeness.io`、链接放置位置不符合要求，均视为未完成申请前置要求。

## 可用能力

入选项目将获得一个或多个公益专用 API Key。Tokeness 会根据项目用途配置额度、模型范围、分组和必要的限制策略。

| 能力 | 说明 |
| --- | --- |
| OpenAI 兼容接口 | 使用 `https://n.tokeness.io/v1` 接入大多数支持自定义 Base URL 的工具 |
| 多模型调用 | 默认以 `DeepSeek-V4-Flash` 为额度基准，可按规则使用其他模型 |
| Key 与额度控制 | 按项目、环境或任务拆分 Key，并设置额度上限 |
| 使用日志 | 在控制台核对请求、模型、状态和消耗 |
| 数据看板 | 观察模型调用趋势和月度消耗 |

## 典型场景

| 项目类型 | 推荐场景 |
| --- | --- |
| 开源项目 | Issue 分类、PR 辅助审查、文档生成、测试用例生成、多语言翻译、贡献者问答 |
| 公益项目 | 志愿者培训、政策问答、服务对象咨询、资料整理、无障碍内容改写 |
| 社会化企业 | 用户支持、知识库问答、教育陪练、运营自动化、报告生成 |

高成本模型、图片生成、长上下文、高并发批处理等场景可能需要单独说明用途，并接受更细的模型范围和额度限制。

## 申请流程

1. 在仓库 `README.md`、官网首页页脚，或无官网且无公开仓库时的项目发布页底部、项目动态末尾、博客文章末尾、公众号文章末尾添加 Tokeness 支持声明。
2. 准备项目介绍、公开链接、使用场景、预计月度 token 需求和影响目标。
3. 将申请材料发送至 <contact@tokeness.io>，邮件标题建议写为 `公益智能扶持申请 - 项目名称`。
4. Tokeness 审核项目真实性、公开鸣谢链接、额度需求和合规风险。
5. 审核通过后，项目方注册或确认 Tokeness 账户。
6. Tokeness 发放公益专用 Key，并配置额度、模型范围和使用限制。
7. 项目按月提交简短使用反馈，Tokeness 根据使用情况决定续期、升档、降档或停止支持。

## 审核标准

| 维度 | 权重 |
| --- | ---: |
| 公共价值和社会影响 | 30% |
| 项目真实性与持续运营能力 | 25% |
| AI 使用场景清晰度 | 20% |
| 额度需求合理性 | 15% |
| 开放性、透明度或可复用价值 | 10% |

Tokeness 优先支持已经有真实用户、受益人、社区、仓库记录或公开服务案例的项目。

## 使用规则

公益额度仅限申请中说明的开源、公益或社会价值场景使用。

禁止行为包括：

- 售卖、转租、转赠公益额度或 API Key。
- 将公益 Key 用于商业分销、代理转发或无关项目。
- 违法违规、侵权、欺诈、攻击、绕过风控、垃圾内容生产。
- 恶意消耗、异常高并发、失控重试或明显偏离申请用途的调用。
- 将 API Key 写入前端代码、公开仓库、截图、群聊或其他不安全位置。

如出现异常请求、重大风险、上游政策变化、长期无反馈或公开鸣谢链接失效，Tokeness 可暂停、限流、调整模型范围、停止后续额度或取消公益资格。

## 续期与反馈

公益支持默认按月复核。项目方需要保留公开鸣谢链接，并按月反馈：

| 项目 | 说明 |
| --- | --- |
| 使用情况 | 本月主要使用场景、调用规模和模型类型 |
| 影响结果 | 服务人数、处理任务数、节省时间、社区贡献或其他可衡量结果 |
| 下月计划 | 预计额度、模型需求和新增使用场景 |

反馈充分、影响明确且使用合规的项目，可申请升级档位。长期无使用、无反馈或用途不清晰的项目，Tokeness 可降低档位或停止支持。
